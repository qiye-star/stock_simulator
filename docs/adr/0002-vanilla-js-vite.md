# ADR 0002：前端采用原生 ES 模块 + Vite，不引入框架

- 状态：已采纳
- 日期：2026-10

## 背景

原版前端是一组原生 JS 文件（`legacy/game.js`、`achievements.js`、`i18n.js` 等）加一个 `index.html`，UI 大量依赖直接操作 DOM。重构的目标是拆分模块、引入构建与测试，但不希望改变用户可见的界面结构。

## 决策

- 语言：原生 ES 模块，代码使用 JSDoc 标注类型，不使用 TypeScript。
- 构建与开发服务器：Vite。产物为 `dist/`，由 nginx 托管。
- 不引入 React / Vue / Svelte 等运行时框架。
- 渲染通过 `ui/html.js` 提供的默认转义 tagged template 完成，禁止直接拼接 `innerHTML`。
- 测试使用 vitest。

## 理由

- 界面结构固定（沿用 `legacy/index.html`），状态量不大，框架带来的收益有限。
- 无框架意味着运行时体积小、没有升级框架的成本，长期维护负担低。
- Vite 只做开发服务器与打包，不改变运行时模型，原有模块可以逐步迁入 `features/`。
- JSDoc + `// @ts-check` 能在不引入 TypeScript 编译链的前提下获得大部分类型提示。

## 后果

- 正面：依赖少，构建快，浏览器原生调试体验好。
- 负面：没有组件生命周期，需要在 `features/` 中约定"挂载 / 卸载"函数，避免事件监听泄漏。
- 负面：大型界面重构时缺少类型系统保障，需要依赖测试覆盖与 JSDoc。
- 若未来界面复杂度显著上升，可以在 `features/` 粒度上局部引入组件库，而不必整体重写。
