# ADR 0004：不提供离线（纯浏览器本地）模式

- 状态：已采纳
- 日期：2026-10

## 背景

原版的全部数据（存档、成就、设置）都保存在浏览器 `localStorage` 中，用户无需服务器即可游玩。重构引入了后端后，需要决定是否保留这一模式。

## 决策

- 重构版必须连接后端才能使用。账号、存档、行情与交易都由服务端处理。
- 前端不实现本地数据库或 `localStorage` 回退，不提供"离线可玩"的分支。
- 旧版数据通过 `POST /import/legacy` 导入：服务端解析旧版导出文本（XOR 编码），将存档挂到当前登录用户名下，忽略原密码。

## 理由

- 双份数据源（本地与服务端）会产生冲突与同步难题，且很难保证行情与补帧在两端一致。
- 确定性行情引擎依赖服务端的 tick 推导（见 [ADR 0003](0003-deterministic-market-engine.md)）。在客户端重新实现一份会带来两套需要维护的规则。
- 账号体系要求数据集中存放，否则多设备与找回存档都无法实现。
- 部署形态已经是 docker compose 一键启动，自托管成本低，"离线"的收益不足以抵消复杂度。

## 后果

- 正面：单一数据源，规则只实现一次（在 `domain/`），前端保持轻量。
- 负面：无法像原版那样直接打开 `index.html` 游玩。需要运行后端（推荐 `docker compose up`）。
- 负面：老用户需要显式导入存档；`legacy/` 仍保留用于对拍与参考，不作为运行时的一部分。
- 若未来确有离线需求，应以"只读回放已下载的存档"的形式实现，而不是复制一套可写的本地引擎。
