## 1. 设计依据：画板 → 实现对照

### 1.1 用户已确认的取舍（必须遵守）
1. 自动交易入口放进“我的”（`#/auto` 保留，变为二级页）。
2. **概率与积分用 `--accent`**，不用红绿（不算行情数据）。红绿只用于价格、涨跌幅、K 线、资金/仓位盈亏、行业涨跌（行情数据）。预测市场的积分盈亏也用中性/强调色（与画板一致；04 §10.1 允许用红绿，本文按画板取中性，见 §8 Q9）。
3. 复盘默认匿名并缩放价格。
4. 预测卡允许“这张不答”。
5. 持仓页保持现状，只把自动交易入口移走。

## 4. 共用模块规格

### 4.1 `SS.clockModel`（`js/lib/clock-model.js`，② 建，④ 扩展；纯函数）

字段来源：07 §1.2 `ClockOut`（REST：`GET /market`、`POST /clock/*`）与 WS `tick.clock`（`minute` 即 `clock_minute`）。真实 store 把它们原样存进 `state.clock`（§5.4），本模块只读不写。

**归一化后的时钟 `Clock2`**：
```
{ rules: "v1"|"v2", minute, trading_day, tick, paused,
  phase: "pre_open"|"morning"|"lunch"|"afternoon"|"closed",
  trading: bool,                        // 此刻能否下单（与暂停无关，07 §1.2）
  next_event: {kind: "open"|"lunch"|"reopen"|"close", minute, at: number|null},   // at = epoch ms（已按 offset 校正到本机时间）
  ms_per_minute: int|null,              // null = 手动推进的存档（挑战停顿期、复盘）
  next_tick_at: number|null, fast_forward_at: number|null,   // epoch ms（已校正）
  offset_ms: int,                       // server_time − 收到响应时的 Date.now()；无 server_time 时 0
  derived: bool }                       // true = 有字段靠推算
```

| 函数 | 规则 |
| --- | --- |
| `phaseOf(m, rules)` | 按 07 §1.3：v1 闭区间（morning `[570,690]`、lunch `(690,780)`、afternoon `[780,900]`、closed `(900,1440)`）；v2 半开区间（morning `[570,690)`、lunch `[690,780)`、afternoon `[780,900)`、closed `[900,1440)`）；pre_open `[0,570)` |
| `tradingOf(m, rules)` | v1 = `phaseOf ∈ {morning, afternoon}`；v2 同（半开区间即撮合窗，07 §4.2） |
| `nextEventOf(phase)` | pre_open→`{open,570}`；morning→`{lunch,690}`；lunch→`{reopen,780}`；afternoon→`{close,900}`；closed→`{open,570}`（次日） |
| `gap(from, to)` | `(to − from + 1440) % 1440` |
| `normalize(raw, {refresh_rate_ms, save_rules})` | `rules = raw.clock_rules ?? save_rules ?? "v1"`；`phase/trading/next_event` 有则用、无则用上面三个函数推算；`next_event.at`、`next_tick_at`、`fast_forward_at` 用 `Date.parse(...) − offset_ms` 转成本机时间（NaN→null）；`ms_per_minute`：字段存在（含 null）则用，缺失时 v1 取 `refresh_rate_ms`、v2 取 `SPEEDS_V2.normal`；缺 `next_event.at` 且未暂停时按 `gap × ms_per_minute` 估算（v1 非交易分钟也按刷新间隔走，07 §1.3） |
| `progress(m)` | 07 §1.3 公式拆成两段：`am = clamp((m−570)/120)`、`pm = clamp((m−780)/120)`；m>900 两段为 1，m<570 为 0 |
| `SPEEDS_V2` / `SPEEDS_V1` | v2：`fast 2500 / normal 5000 / slow 7500`（ms/分钟，约 10 / 20 / 30 分钟一天，07 §5.1）；v1：刷新间隔 `1000 / 3000 / 5000`（一天交易时段 242 分钟 ≈ 4 / 12 / 20 分钟） |
| `speedOf(rules, user)` | v2 返回 `user.clock_speed ?? "normal"`；v1 返回与 `refresh_rate_ms` 最接近的档 |
| `view(c, {now, t0_mode})` → `TradeBarView` | 见下 |
| `formatReal(ms)` | `< 60 000` →“不到 1 分钟”；`< 3 600 000` →“约 N 分钟”（四舍五入，最少 1）；否则“约 H 小时 M 分” |
| `formatCountdown(ms)` | `< 60 s` →“8 秒”；否则 `m:ss`；`≥ 1 h` →`h:mm:ss`；负数按 0 |

`SS.fmt.dayNo(d) = d + 1`（加到 `js/lib/format.js`）：所有面向用户的交易日序号（“第 N 个交易日”“D{n}”“第 15 日揭晓”）一律经它，后端字段保持从 0 起。

**`TradeBarView`**：
```
{ state: "live"|"paused"|"dwell"|"closed"|"pre"|"manual",
  statusText,          // 交易中 / 已暂停 / 午间休市 / 已收盘 / 待开盘 / 手动推进
  classic: bool,       // rules === "v1"，状态行追加 .tag “经典节奏”（07 §7.4 第 2 条）
  dayText,             // “第 12 个交易日 · 上午盘”（dayNo(trading_day) + phaseText）
  timeText,            // “10:42”（fmt.clock(minute)）
  nextMain, nextSub,
  progress: {am, pm},
  countdown_ms: number|null,   // 有值时组件开 1 s 计时器
  action: null|"resume"|"skip" }
```
N = `gap(minute, next_event.minute)`（游戏分钟）；`remain = next_event.at − now`（`at` 为 null 时 null）。

| 情形 | state | nextMain | nextSub | action |
| --- | --- | --- | --- | --- |
| paused（任意相位；`at` 为 null） | paused | 按相位同下 | “行情已暂停” | resume |
| morning | live | “距午休 N 分钟”（N≤1 时“即将午休”） | “现实约 {formatReal(remain)}” | — |
| afternoon | live | “距收盘 N 分钟” | 同上 | — |
| lunch · v2（11:30 停留或 12:59） | dwell | “午间休市” | “{formatCountdown(remain)}后下午开盘” | — |
| lunch · v1 | dwell | “距下午开盘 N 分钟” | “现实约 X” | skip |
| closed · v2 | closed | “已收盘” | “{formatCountdown(remain)}后进入{第 dayNo(d+1) 个交易日}” | —（由收盘小结负责） |
| closed · v1 | closed | “距明日开盘 N 分钟” | “现实约 X” | skip |
| pre_open（v2 的 9:29） | pre | “即将开盘” | “{formatCountdown(remain)}后开盘” | — |
| pre_open · v1 | pre | “距开盘 N 分钟” | “现实约 X” | skip |
| `ms_per_minute === null`（挑战停顿、复盘） | manual | 由 overlay 提供（§5.7） | 同 | — |

v2 的“现实约 X”直接取 `next_event.at`（服务端已算好，含停留时长）；只有缺 `at` 时才用 `N × ms_per_minute` 估算。`countdown_ms` 在 dwell/closed/pre 三种 v2 情形为 `remain`，其余为 null（交易时段只按 tick 刷新分钟级文字）。v1 下 `trading_day` 一个时钟日内会多次变化（00 决策 7），说明弹层写明老存档节奏。

测试 `tests/clock-model.test.mjs`：两种规则的相位端点（569/570/689/690/691/779/780/899/900/901）、`gap` 跨日、v1 缺字段推算（`ms_per_minute = refresh_rate_ms`、`at = now + gap×ms`）、v2 字段优先与 `server_time` 偏差校正、`ms_per_minute=null` → manual、`formatReal` 边界（59 999/60 000/3 600 000）、`view` 每个情形的 `nextMain/nextSub/action`。

#### 5.6.1 `js/lib/predict-math.js`（`SS.predictMath`，纯函数，测试 `tests/predict-math.test.mjs`）
| 函数 | 规则 |
| --- | --- |
| `probsFromPick(pick, confPct, k)` | 02 §5.2：`100−conf` 平分给其余 k−1 档，余数按“离 pick 近优先、同距下标小优先”逐个 +1。用例：`(3,70,5)→[7,7,8,70,8]`、`(1,80,2)→[20,80]`、`(2,20,5)→[20,20,20,20,20]` |
| `argmaxPick(probs)` | 唯一最大值的下标，并列返回 null |
| `confRange(k)` | `{min: k===5 ? 20 : 50, max: 100, step: 5, def: k===5 ? 50 : 70}`（02 §4 常量） |
| `bucketLabels(edges_bp)` | `[-600,-200,200,600]` → `["<−6%","−6~−2","−2~2","2~6","≥6%"]`；数值 `bp/100` 去尾零；负号用“−”（U+2212） |
| `bucketRangeText(i, edges_bp)` | 结算页“落在第 4 档（2%~6%）” |
