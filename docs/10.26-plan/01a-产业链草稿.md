## 1. 定义说明

### 1.1 列含义（列名、列序固定，供脚本无损转换）

| 列 | 取值 | 含义 |
| --- | --- | --- |
| 上游 | 行业标签 | `supply` / `demand` 边里是**真实的上游**（供货方）；`substitute` / `same_theme` 边里只是 A 端，无方向含义 |
| 下游 | 行业标签 | `supply` / `demand` 边里是**真实的下游**（采购方）；`substitute` / `same_theme` 边里只是 B 端 |
| 关系类型 | `supply` / `demand` / `substitute` / `same_theme` | 见 1.2 |
| 正负 | `+` / `-`（ASCII 减号） | 见 1.3 |
| 强度 | 1 / 2 / 3 | 1 弱、2 中、3 强 |
| 滞后 | 0–5 的整数 | 冲击到达目标行业的交易日数，0 = 当日 |
| 说明 | 一句话 | 传导机制；来自种子的以“[种子]”开头，并注明申万原关系 |

### 1.2 关系类型与传导方向

| 类型 | 冲击源 → 目标 | 典型场景 |
| --- | --- | --- |
| `supply` 供应 | **上游列 → 下游列** | 上游减产、涨价、停产，下游成本或供给受冲击（煤价涨 → 火电承压） |
| `demand` 需求 | **下游列 → 上游列**（与 supply 反向传） | 下游景气或萎缩，上游订单随之变化（地产新开工 → 水泥） |
| `substitute` 替代 | 双向，两端对称 | 一方受损另一方受益，正负恒为 `-`（燃油车 ↔ 电动车） |
| `same_theme` 同题材 | 双向，两端对称 | 资金面、政策面同涨同跌，无实际买卖关系，正负恒为 `+`（人工智能 ↔ 芯片） |

一对行业往往同时存在供应和需求两种机制。本表**每对只保留主导的一条**：上游是大宗原料、成本占比高的记 `supply`；上游是设备、零部件、服务，主要靠下游订单驱动的记 `demand`。

### 1.3 正负号的统一定义

**正负 = 冲击源行业的股价受到正面冲击（上涨）时，目标行业股价的方向。** `+` 同向，`-` 反向。负面冲击把符号整体取反即可。

- `supply` 边：上游的“正面股价冲击”通常来自**减产、涨价**，对下游是成本上升，所以记 `-`。反过来，上游扩产降价时上游股价受负面冲击，乘以 `-` 后下游得到 `+`，与“扩产降价利好下游”一致。本稿的 supply 边**全部为 `-`**。
- `demand` 边：下游景气（股价 +）带来上游订单增加，本稿的 demand 边全部为 `+`。
- `substitute` 恒为 `-`，`same_theme` 恒为 `+`。
- 事件对**事发行业自身**的股价方向不由本表决定，由事件模板给出。例如“某锂矿停产”：对锂资源板块可能是 +（锂价上涨），也可能是 −（个股自身受损）。本表只负责行业之间的传导。

### 1.4 强度与滞后（给引擎的建议，不是硬约束）

- 强度建议的传导系数：1 → 0.2–0.3、2 → 0.4–0.5、3 → 0.6–0.8（目标冲击 = 源冲击 × 系数）。单 tick 噪声是 ±2%，强度 1 的边只适合传导大事件，否则会被噪声淹没。
- 滞后：同题材、替代边一般为 0（资金面当天反应）；燃油、原料这类直接成本为 0–1；需要等报价、财报或开工数据确认的为 2–3。
- 多跳传导建议最多 2 跳，每跳再乘衰减系数，避免冲击在环路里放大。本表存在环路，例如 钢铁→房地产←建材→基建←钢铁。
