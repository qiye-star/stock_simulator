## 1. 一句话

游戏内生成公告、新闻、政策、突发和传闻。冲击从事发行业出发，沿产业链上下游逐级传导（有强度、有延迟、有正负号）。玩家既可以用模拟资金交易，也可以对重大事件做预测拿积分。

可试玩的玩法示意页：https://claude.ai/artifact/1HbJZbiTsJv1gt8exKhN8j （示例数据是手写的，仅示意体感）。

补充共识（来自讨论）：
- 不是独立游戏，是现有存档里的一层玩法。**按存档开关**：引擎是确定性的，老存档加事件会改变未来走势，所以新建存档时选择是否开启“事件模式”，老存档默认关闭。
- 开启事件模式后，交易与预测是同一存档里的两种得分方式：交易看资金盈亏，预测看积分。
- C 每日挑战有单独入口，系统发一个临时挑战存档，玩法与 A+B 一致。E 真实复盘是独立模式，不走合成行情引擎。

## 3. 必须遵守的项目约束（摘自各级 CLAUDE.md / docs/CONTRACT.md）

- 金额整数分（`*_cents`）；涨跌幅基点 / ppm 整数；时间 UTC。
- `backend/src/stocksim/domain/` 是纯函数：零 I/O，禁止 import sqlalchemy/fastapi、`datetime.now`、全局随机。随机只能用 `domain/rng.py` 的 splitmix64（`rand_below(seed, tick, stock_idx, k, n)`）。现有占用：交易 tick 上 k=0 涨跌、1 彩蛋幅度、2 成交量扰动、100+ 五档；init（tick=-1）上 k=0、1、2+4i…；开局分钟 `tick=-2, idx=0, k=0`。新增段：A 事件日 `tick=-(2^32)-d`、存档参数 `-(2^32)+4096`；B 预测出题 `-(2^34)-d`；时钟 v2 共同因子 `idx=400, k=0`（交易 tick 上）、日档位 `tick=-(2^33)-d`（idx 0..384，k 0–3）。新功能必须另划不冲突的段并写进文档。
- 行情推进只在 `services/market.py::_run_ticks`；`intraday` 分时由 `domain.advance` 逐 tick 重放并校验终点，**事件漂移必须同样可重放**，否则分时会退化为 `exact=false`。
- 改 model 必须配 Alembic 迁移（`render_as_batch=True`），`uv run alembic check` 无漂移；新错误码同步 `core/errors.py`、`docs/CONTRACT.md`、前端 `i18n/errors.js` 与两份 locale。
- 改 API 同步 `frontend/src/api/endpoints.js` 的 typedef（以 `backend/src/stocksim/schemas/*.py` 为准）；手机端 `mobile-prototype/` 已对接真实后端，也要同步（`js/lib/store.real.js` 与 `store.js` 同名方法）。
- 每个新目录都要 `CLAUDE.md` + `README.md`（中文）。
- 行情噪声分版本（07 §4.3）：v1 单 tick 随机波动 ±2%、`TICKS_PER_TRADING_DAY=20`；v2 每交易日 242 tick、次日 9:30 换日，单股日 σ 约 2.3%。涨跌停均为 ±10%。事件信号强度必须相对所在版本的噪声来设计，太小会被噪声淹没。
- **seed 安全**：`services/saves.py` 导出 JSON 含 `market_seed`。挑战/预测市场场景下拿到 seed 就能算出未来 K 线，必须服务端保密（开局公布 seed 哈希作承诺，结算后再公布）。

### 5.3 预测与计分
| 项目 | 借什么 |
| --- | --- |
| forecast-arena（MIT，Flask+SQLAlchemy） | 最贴合：LMSR 市场、结算、Brier 排行；AI 交易员 = 原型参数 + `_rng(seed,"archetype",i)` 扰动，LLM 每个原型只调一次。`services/market_service.py`、`settlement_service.py`、`scoring_service.py`、`population_service.py` |
| marketsim（MIT） | 125 行 LMSR `src/marketsim/amm.py`；Brier/log loss/校准表 `metrics.py` |
| Manifold（MIT） | CPMM 对照 `common/src/calculate-cpmm.ts`（多选需几千行套利，不采用） |
| Metaculus（BSD-2） | 同伴分/基线分 `scoring/score_math.py` |
| Quantified Intuitions（MIT） | Pastcasting（对已有答案的历史问题预测，含多人）≈ 每日挑战；区间评分 `lib/services/scoring.ts` |
| Fatebook（MIT） | 校准图 `components/CalibrationChart.tsx` |
| llm_trading_sim | 交易员性格提示词 `src/agents/prompts/*.md`（contrarian、herd_follower、momentum…） |

已有结论：
- 预测市场用 **LMSR**：`C(q)=b·ln Σe^{q_i/b}`，`p_i=e^{q_i/b}/Σe^{q_j/b}`；做市商最大亏损 `b·ln n`；买入向上取整、卖出向下取整防刷；份额整数、每份兑付 100 积分；logsumexp 保数值稳定。
- 方向+幅度分档题用 **RPS**：`RPS = 1/(K−1)·Σ_{k<K}(F_k−O_k)²`，得分 `round(100·(1−RPS))`。
- 产业链排序题用 **NDCG@3**：真实前三相关度 3/2/1，`DCG=Σ(2^rel−1)/log₂(i+1)`，得分 `round(100·DCG/IDCG)`。
- 多人排行用 Metaculus **同伴分** `100·(ln p_i − 他人 ln p 的均值)`；单人用基线分。
- 校准度：按置信度分 10 档画“实际命中率 vs 声称置信度”。

## 6. 跨文档共享的约定（各分册必须一致）

- **事件模式开关**：存档级字段，01 定义；B/C/D 只读取。
- **事件对象与事件 ID**：由 `(seed, trading_day, slot)` 确定性生成，不落库也能重建；01 定义结构与 ID 规则，B/C/D 引用。
- **积分账本**：02（预测卡）定义并拥有积分账本表与流水；C、D、E 只通过它记账（挑战奖励、市场买卖与兑付、情报卡消费、复盘积分）。没有系统账户，D 的做市补贴记在 D 自己的表（02 §1.1、04 §1.1）。
- **计分纯函数**：02 在 `domain/` 定义 RPS / NDCG / 同伴分等，C、D、E 复用；出题口径函数 `structure_for`、`change_bp_for`、`bucket_edges_bp`、`validate_answers` 也归 02（02 §1.3）。
- **存档类型**：`saves.mode` 取值全集与 `LISTED_MODES` 计数规则由 03 定义，06 §3.4 登记。
- **时间基**：每日 tick 数由存档 `clock_rules` 决定，所有分册经 `TimeBase` 取值（01 §1.9）；规则集身份为 `(clock_rules, events_ruleset)`。
- **seed 保密与承诺**：03 定义（挑战存档），04 复用。
- **E 复盘**：独立数据管道与独立存档类型，不复用合成引擎，但复用 02 的计分与积分账本。
