# scripts（辅助脚本）— 给 agent 的说明

- `convert_stockdata.py`：`legacy/stockData.js` -> `backend/src/stocksim/data/{stock_pool,industries}.json`。
  - 只读 legacy，幂等，会断言 385 只且代码唯一，并给影视飓风（999999）标记 `profile=bull_bias`。
  - 运行：`python3 scripts/convert_stockdata.py`（仅用标准库，无需 uv）。
- `e2e_smoke.py`：对运行中的后端做 HTTP 冒烟（`BASE_URL`，默认 `http://localhost:18000`）。`s_challenge`（每日挑战，仅 `E2E_CHALLENGE=1` 时执行，否则打印 SKIP）：服务端需 `CHALLENGE_SCHEDULE=compact CHALLENGE_MIN_ACCOUNT_AGE_HOURS=0 ENABLE_DEBUG_API=true CHALLENGE_SEED_KEY=<任意串>`；流程为注册 6 人 → `debug/challenges/ensure` → 轮询 running → 全员报名 → 轮询第 1 回合 open → 各自作答 → 2 人停顿期下单 → `debug/challenges/{id}/shift` 快进结算 → 日榜 6 人与名次校验 → reveal 的 sha256 校验 → 挑战存档 `clock/skip` 得 409 `CHALLENGE_UNSUPPORTED`。`call()` 支持 `opener=` 以便多用户各自持 Cookie。只用标准库（urllib + http.cookiejar）。步骤：注册随机用户 -> 建存档 -> 读行情 -> 买 100 股 -> 当日卖出应得 `TRADE_T1_SELL_BLOCKED` -> 持仓 -> 自选 -> 自动交易条件单 -> 导出。非交易时段需要服务端 `ENABLE_DEBUG_API=true`。末尾含 `s_clock_v2`：v2 存档一交易日循环（8 次跳过、收盘小结、换日、`clock_speed` 节奏档）。 `s_events`：v2 事件存档（01 §11 第 9 步）：产业链 82 节点且强度为 null → 循环跳过至交易日 ≥2 → `/news?major=true` 至少 1 条 → `/events/{id}` 详情与传导回放 → 关闭事件的存档 `/news` 得 409 `EVENTS_DISABLED`。
  - 启动：`cd backend && uv run uvicorn --factory stocksim.main:create_app --port 18000`（main.py 没有模块级 `app`，不要用 `stocksim.main:app`）。
- `convert_supply_chain.py`：`docs/10.26-plan/01a-产业链草稿.md` 的边表 → `data/supply_chain.json`（校验行业名/重复/符号/强度/滞后，计算 layer）。`--check` 只校验并检查产物是否最新；`--to-md` 把 JSON 反向输出成同列序的 markdown 表（往返无损）。人工校对 01a 后直接重跑。
- `build_stock_exposure.py` + `stock_exposure_overrides.json`：生成 `data/stock_exposure.json`（龙头与跨行业暴露度）。默认每行业股票池第 1 只为龙头（≥8 只的行业前 2 只），再合并覆盖文件。`--check` 同上。
- `news/`：离线文案流水线（见 `news/CLAUDE.md`），产物 `data/news_templates.json`。
- `clock_v2_sim_report.py`：时钟 v2 波动标定（`--seeds 3 --days 60 [--check]`，多进程，全量 385 只，只 import `stocksim.domain`）。CI 用 `--seeds 2 --days 40 --check`。不达标只调 `domain/market_engine.py` 的 `V2_*` 常量；v2 金值发布后冻结。
- `event_sim_report.py`：事件行情仿真调参报告（`--clock-rules {1,2}` 选时钟版本，默认 1；v1 `--seeds 20 --days 300`，v2 `--clock-rules 2 --seeds 20 --days 120`，两版都必须达标；多进程；空闲 16 核约 3 分钟，机器繁忙时可达十几分钟），按 01 §12.3 验收；不达标只调 `domain/events/constants.py`。只 import `stocksim.domain`，不在这里放业务逻辑。
- 脚本应保持纯标准库、可重复运行；不要在此放业务逻辑（业务在 backend/src）。
- 修改输出格式后，同步更新 `backend/tests/unit/data/` 中的断言。
- `e2e_smoke.py` 新增 `s_predictions`（预测卡）：事件 v2 存档 → 余额 200 → 跳过至出卡 → 作答并继续 → 跳过至首张卡结算 → 余额 = 200 + 积分 → 买边 L1 → 关闭事件存档 /predictions 得 409。- `pm_prior_report.py`（预测市场公开基率先验，04 §4.5）：只 import `stocksim.domain`，纯标准库，读 `backend/src/stocksim/data/*.json`，v2 时钟。逐 tick 推演行情，对每个重大事件用 `contracts_for_event` 取 bucket 合约（窗口与档位与挑战一致），按服务层真值口径结算，按 (scope, sentiment) 统计 5 档频率；每组截到 `PRIOR_FLOOR_PPM` 后归一为和 1e6 的整数 ppm。`--seeds 20 --days 120`（多进程，确定性）。`--check` 校验 `domain/prediction_market/constants.py::BUCKET_PRIOR_PPM` 与统计一致，不一致退出码 1；改了事件或行情常量后重跑并把输出片段贴回常量。
- `prediction_sim_report.py`（02 §13.4，B12）：只 import `stocksim.domain`，纯标准库，读 `backend/src/stocksim/data/*.json`。`--seeds --days --clock-rules 1|2`。输出方向题档位分布、档位方向与 sentiment 一致率、排序题出题率、均匀/只看标题/理想答案的平均分。不达标只调 `backend/src/stocksim/domain/predictions/constants.py`。
- `e2e_smoke.py` 新增 `s_replay`（真实复盘，E3.4）：仅 `REPLAY_SMOKE=1` 时执行（否则打印 SKIP）。服务端需以 `REPLAY_PACKS_DIR=<含 fixture-min/v1.json 的目录>` 启动（夹具来自 `backend/tests/fixtures/replay/pack_min.json`，不联网）。流程：列关卡 → 建会话 → 推进到开盘买入 → `next_day` 停在 question_open → 作答两题 → 推进到结算 → 揭示（真实代码可见）。`REPLAY_SLUG` 可覆盖关卡 slug。
- `e2e_smoke.py` 新增 `s_prediction_market`（仅 `E2E_CHALLENGE=1` 时执行，先于 `s_challenge`）：注册 → `ensure`（明天的挑战，避免与 `s_challenge` 冲突）→ `debug/prediction-markets/sync` 轮询到开市 → quote → 带 `Idempotency-Key` 买 2 份 → 同键重放得 `replayed` → 卖 1 份 → `debug/challenges/{id}/shift` 快进 → `/me/prediction-settlements` 有记录 → 积分余额 = 初始 − 买入花费 + 卖出回款，且 `/points/ledger` 首条 `balance_after` 等于余额。`call()` 新增 `headers_extra` 参数。
